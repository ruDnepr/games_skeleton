# Игры для Дианы

Общая основа для детских настольных игр на Flutter (Android и iOS). Здесь уже есть всё, что не зависит от конкретной игры: заставка, главное окно, список игр, экраны «Правила» и «Настройки», звук и настоящая сетевая игра по локальной сети. Сама игровая логика — заглушка: у каждой игры будут свои правила, свои переключатели и своя партия.

Все тексты и интерфейс — на русском. Шрифт Nunito и звуки лежат внутри приложения: ни интернет, ни аккаунты не нужны, а сеть работает только в одной локальной сети Wi-Fi.

Сейчас в каталоге одна игра — **«Игра-пример»**. Это не игра, а шаблон: её правила объясняют, как устроен каркас, переключатели показывают, как игра объявляет свои настройки, а экран партии честно говорит, что партии ещё нет. Новая игра добавляется копированием этой папки (см. «Как добавить новую игру»).

## Что уже работает

- Заставка (850 мс появления, переход в главное окно через 1500 мс) и главное окно с двумя большими кнопками.
- «Играть» → список игр → карточка игры → её правила, её настройки, её партия.
- «Сетевая игра» → выбор игры → создание или поиск игры в Wi-Fi.
- «Правила» из меню показывают правила первой игры каталога; «Настройки» из меню — общий блок настроек.
- Сетевая игра целиком: mDNS-поиск, WebSocket-сервер и клиент, код из шести символов, адрес `IP:порт` как запасной путь, рукопожатие с проверкой версии и игры, ping/pong.
- Звук из пула плееров, с ограничением наложения и тишиной в фоне.

## Сборка и запуск

- Flutter **3.47.8** (Dart 3), Android SDK / Android Studio для Android.
- Для iOS: macOS, Xcode и настроенные инструменты Flutter для iOS. Для установки на iPhone нужна настройка подписи в Xcode.

```sh
flutter pub get
flutter analyze
flutter test
flutter run                              # выбранное устройство
flutter build apk --debug                 # Android
flutter build apk --release               # Android, подписан отладочным ключом
flutter build ios --simulator --debug --no-codesign # iOS, на macOS
```

Идентификаторы приложения: Android `ru.dnepr.games_for_diana`, `targetSdk = 36`; iOS bundle id `ru.dnepr.gamesForDiana`, имя `games_for_diana`, отображаемое имя «Игры для Дианы». Разрешения сети уже прописаны: на Android — `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE` и `CHANGE_WIFI_MULTICAST_STATE` (без последнего mDNS не ищет хоста), на iOS — `NSLocalNetworkUsageDescription` и `NSBonjourServices` с `_diana-games._tcp`.

## Как добавить новую игру за пять шагов

1. **Скопируй папку** `lib/games/example/` в `lib/games/<id>/`, где `<id>` — латиница без пробелов (`ludo`, `memory`, `dots`). Идентификатор попадает в ключи хранения и в сетевое рукопожатие, поэтому после первых партий его не меняют.
2. **Заполни данные игры.** В `rules.dart` — список `RuleCard` (номер, заголовок, текст), в `settings.dart` — список `GameSetting` (ключ, заголовок, подпись, иконка, значение по умолчанию). Экран правил и блок переключателей строятся из этих списков, писать экраны не нужно.
3. **Опиши сеть своей игры** в `network.dart`: `options(settings)` — что игра рассказывает сопернику; `parseOptions(map)` — обратный разбор, который бросает `FormatException` на чужие данные; `validateMove(move)` — проверка присланного хода по правилам игры.
4. **Открой партию** в `session_page.dart`: это экран, куда ведёт кнопка «Играть» на карточке и куда `NetworkPage` передаёт живое соединение. Если `network` не `null`, читай ходы соперника из `network.service.events` и проверяй каждый через `validateMove`, а свои отправляй через `network.service.send`.
5. **Добавь игру в каталог** — единственное место, где перечислены игры, — в `lib/app/catalog.dart`:

```dart
static final List<GameDefinition> games = List.unmodifiable([
  exampleGame,
  myGame,
]);
```

Больше ничего менять не нужно: главное окно, список игр, правила, настройки, сетевое лобби и звук общие. Заголовок карточки, слоган, иконка и цвет берутся из `GameDefinition`.

### Контракт игры

`GameDefinition` (`lib/games/definition.dart`):

| Поле | Что это |
|---|---|
| `id` | латинский идентификатор: ключи настроек `game.<id>.<key>`, поле `gameId` в рукопожатии |
| `title`, `tagline` | крупная строка и подпись на карточке, на экране партии и в приглашении по сети |
| `icon`, `accent` | иконка и цвет карточки из палитры |
| `rules` | `List<RuleCard>` — карточки `1..N` экрана правил, в том порядке, в котором их вернули |
| `settings` | `List<GameSetting>` — переключатели этой игры |
| `start(context, settings, {network})` | куда ведёт «Играть»; `network` заполнен, когда друг подключился |
| `options(settings)` | `Map<String, Object?>` с настройками игры для соперника |
| `parseOptions(map)` | обратный разбор с проверкой; `FormatException` на чужие данные |
| `validateMove(move)` | проверка присланного хода; `FormatException`, если ход невозможен |
| `hostSide(settings)` | место хоста в игре (у заготовки — метка `host`) |

## Экраны и оформление

Палитра и типографика живут в `lib/presentation/theme.dart`: `ink #3D3154`, `muted #8B8298`, `purple #8266D5`, `deepPurple #6047AF`, `cream #FFF8ED`, `yellow #FFD66D`, `peach #FFD9C7`; шрифт Nunito; кнопки — не ниже 48×54 с радиусом 18; карточки — радиус 22 и белый фон; диалог — радиус 28.

- **Главное окно** — до 480 по ширине, заголовок 37 px с межбуквенным −1.2, бейдж «ИГРАЕМ ВМЕСТЕ ✦», подпись «Думай, играй и улыбайся!». Две большие кнопки: «Играть» («Выбери свою игру») и «Сетевая игра» («С другом по Wi-Fi», жёлтая). Ниже — «Правила» и «Настройки», под ними «Каждая партия — маленькое приключение ✨», а после первой партии — «Сыграно партий: N · Побед: M».
- **Заставка** — «Игры для Дианы» и «Время играть и улыбаться!», появление за 850 мс (`Curves.elasticOut`, масштаб .75 → 1), переход в главное окно через 1500 мс.
- **Логотип** — наклонённая подложка с тенью, сетка вместо позиции, два жетона и звёздочка.
- **Правила** — бейдж «УЧИМСЯ ИГРАЯ», заголовок «Это просто!», карточки выбранной игры и внизу «Ошибаться и пробовать снова — это нормально! ✨».
- **Настройки** — бейдж «ВСЁ ПОД ТЕБЯ», заголовок «Как тебе удобнее?», затем переключатели игры, звук, имя и сброс прогресса.

Все диалоги — только через `showDianaDialog`: кнопки в столбик, во всю ширину, высотой 56; безопасный выбор стоит первым и нарисован заполненным. Ряд действий Material сжимает русские подписи до нечитаемого размера — именно поэтому диалоги свои.

## Сетевая игра

Транспорт целиком лежит в `lib/network/`: `protocol.dart` — общий конверт, `network_game_service.dart` — mDNS, сервер, клиент, рукопожатие и heartbeat.

1. **Создать игру.** Хост поднимает `shelf_io`-сервер на свободном порту и объявляет службу `_diana-games._tcp` через `nsd` с именем `Diana-<КОД>` и ником игрока в TXT-записи. На экране появляются код из шести символов (алфавит без похожих `0/O`, `1/I/L`) и адрес `IP:порт` на случай, если поиск не работает.
2. **Найти игру.** Клиент ищет объявления в той же сети, показывает найденные игры или принимает код вручную. Можно ввести адрес `192.168.1.10:12345` — это запасной путь, когда mDNS ничего не нашёл (гостевая сеть, изоляция клиентов, отключённый multicast).
3. **Рукопожатие.** Клиент присылает `hello` с версией протокола, кодом и именем. Хост отвечает `gameConfig` — общим лобби `LobbyConfig`: `version`, `gameId`, `hostSide`, `code`, `hostName`, `options`. Устройство принимает лобби только если совпала версия протокола, `gameId` есть в каталоге **и** `game.parseOptions(options)` не бросил исключение. Иначе — вежливый отказ «У вас разные версии игры» до начала партии, а не расхождение позиций посреди игры.
4. **Партия.** Дальше идут сообщения `move`, `undoRequest`, `undoResponse`, `resign`. Ходы разбирает и проверяет игра: `validateMove` вызывается до применения, а не после. Полная доска и история не пересылаются — только действия.
5. **Живучесть.** `ping` каждые 10 секунд и контроль тишины: если от соперника ничего не приходило 30 секунд, связь считается потерянной. Телефон в соседней комнате уходит в сон и без этого молча теряет соединение — снаружи это выглядит как «зависла игра».
6. **Отказы.** Чужой код, чужая игра, чужая версия протокола и незнакомые опции — всё это `FormatException` и вежливое сообщение на экране; второй экземпляр `NetworkGameService` не создаётся, лобби владеет соединением и закрывает его вместе с собой.

mDNS — только для поиска: код, проверка версии и проверка игры остаются на месте всегда. **Важно:** поиск через `nsd` между двумя реальными устройствами ещё не проверялся живьём. Его нужно проверить на двух телефонах в одной сети: хост видит «Ждём друга…» и код, гость находит игру в списке «Игры рядом»; отдельно проверить подключение по адресу `IP:порт`. Пока это не сделано, надёжным считается только ручной адрес.

## Звук

`lib/app/sounds.dart` — единственное место, откуда играет звук. Восемь коротких сэмплов в `assets/audio` (`move`, `capture`, `crown`, `guess`, `miss`, `win`, `lose`, `draw`) готовятся один раз при запуске: `PoolsSfxBackend` создаёт на каждый файл пул `FlameAudio.createPool` не больше чем на два голоса.

Почему не `FlameAudio.play`: он создаёт новый `AudioPlayer` на каждый вызов и не освобождает его. На Android это общий `SoundPool` с пределом в 32 потока и без события завершения: после десятков ходов новые звуки уже не играют (молчит победа и ничья), а старые потоки начинают звучать сами по себе и накладываются друг на друга.

Правила шины (`GameSounds`): выключенный звук молчит; один и тот же сэмпл не звучит дважды в пределах 90 мс; звуки хода не накладываются друг на друга; звук финала проходит сразу после хода; в фоне (`AppLifecycleState`) не играет ничего. Звук окончания партии выбирает `resultSoundName`: победа, мягкий проигрыш или спокойная ничья.

Подключить звук в партии так:

```dart
final sounds = GameSounds(settings);
sounds.play(GameSound.move);                       // ход
sounds.play(resultSoundName(draw: false, local: true, iWon: true));
```

## Настройки

`SettingsController` (`lib/app/settings.dart`) хранит общее и по игре:

- общее: `sound`, `nickname`, `gamesPlayed`, `gamesWon`;
- по игре: `flag(gameId, key)` и `setFlag(gameId, key, value)` с ключом `game.<id>.<key>`. Значение по умолчанию берётся из `GameSetting.defaultValue`, поэтому игры не пересекаются и не зависят от порядка загрузки.

Имя тримится, обрезается до 20 рун, пустое заменяется на «Диана», а запись того же значения не уведомляет слушателей — поэтому поле имени не пересобирается на каждый символ и клавиатура на Android не закрывается. Поле ввода — отдельный виджет со своим `TextEditingController` и `FocusNode`: текст сохраняется по «Готово», при уходе фокуса и при уходе со страницы.

- `test/application/settings_test.dart` — сохранение и восстановление настроек; флаги разных игр не пересекаются; повторная запись не уведомляет.
- `test/network/protocol_test.dart` — код из шести символов только из разрешённого алфавита; декодирование сообщений; неизвестный тип и сообщение больше 16 КБ отвергаются; `LobbyConfig` не проходит с чужой версией, чужим `gameId` и негодными `options`.
- `test/network/lan_test.dart` — два экземпляра `NetworkGameService` на `localhost`: хост поднимается, клиент подключается по адресу и порту, лобби доходит и разбирается игрой, ходы идут через `send`/`events` в обе стороны, отмена подтверждается, после `close()` состояние `disconnected`, а чужая версия протокола получает вежливый отказ. Сеть в тестах не зависит от mDNS: соединение идёт по `IP:порт`.
- `test/games/example_game_test.dart` — контракт игры на примере: уникальные латинские `id`, карточки правил `1..N`, ключи переключателей и их значения по умолчанию, опции через общий конверт, проверка формата хода.

CI — два задания:

- **Android: анализ, тесты и APK** — `flutter analyze`, `flutter test`, затем `app-debug.apk` и `app-release.apk`; оба файла лежат в артефакте `diana-games-apk`. Release подписан отладочным ключом: ставится на телефон, но не годится для Google Play. Шаг с тестами на эмуляторе включается только вручную (`Run workflow`) и не блокирует сборку; в заготовке сценариев для устройства ещё нет, поэтому скрипт `tool/run_integration.sh` честно сообщает, что запускать нечего. Логи устройства при сбое уходят в `diana-games-device-logs`.
- **iOS: сборка без подписи** — `flutter build ios --simulator --debug --no-codesign`, приложение для симулятора в артефакте `diana-games-ios-simulator`.

Новый коммит в ту же ветку отменяет предыдущий прогон, поэтому одновременно висит не больше одного запуска. Тесты на `localhost` и сборка не заменяют проверку на телефонах: mDNS, звук из динамика и установку на устройство надо смотреть руками.

## Что стоит помнить, добавляя игру

- Игровой экран: всё, кроме поля, имеет фиксированную высоту, поле получает остаток — иначе оно дёргается при смене текста и появлении кнопок. Полотно игры строится один раз и оборачивается в `RepaintBoundary`. Не больше двух кнопок действия в ряду, подпись не уменьшается (многоточие вместо масштабирования).
- `SwitchListTile` и `ListTile` только на `Material`, не на цветном `Container`: иначе Flutter в debug ругается, что фон и волны нажатия скрыты, а в release волн нажатия нет.
- Присланный по сети ход проверяется правилами игры до применения, а отказ при несовпадении версии или игры происходит до начала партии.
- Два экземпляра `NetworkGameService` не нужны: лобби создаёт один и передаёт его партии.
- Иконки приложения рисует `tool/make_icon.py` (нужен Pillow): он перезаписывает `mipmap-*` на Android и все размеры в `ios/Runner/Assets.xcassets/AppIcon.appiconset`. Иконка повторяет логотип главного окна — наклонённая сетка, два жетона и звёздочка, — и иконки iOS сохраняются без прозрачности, как требует App Store.
