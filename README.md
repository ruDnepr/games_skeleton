# Игры для Дианы

[![Flutter](https://github.com/ruDnepr/games_skeleton/actions/workflows/ci.yml/badge.svg)](https://github.com/ruDnepr/games_skeleton/actions/workflows/ci.yml)

Платформа детских настольных игр на Flutter (Android и iOS). Девять игр в одном приложении: заставка, главное окно, список игр, экраны «Правила» и «Настройки», звук и настоящая сетевая игра по локальной сети — общие. Правила, настройки и сама партия — у каждой игры свои.

Все тексты и интерфейс — на русском. Шрифт Nunito и звуки лежат внутри приложения: ни интернет, ни аккаунты не нужны, а сеть работает только в одной локальной сети Wi-Fi.

## Что уже работает

- Заставка (850 мс появления, переход в главное окно через 1500 мс) и главное окно с двумя большими кнопками.
- «Играть» → список игр → карточка игры → её правила, её настройки, её партия.
- «Сетевая игра» → выбор игры → создание или поиск игры в Wi-Fi.
- «Правила» из меню показывают правила первой игры каталога; «Настройки» из меню — общий блок настроек.
- Сетевая игра целиком: mDNS-поиск, WebSocket-сервер и клиент, код из шести символов, адрес `IP:порт` как запасной путь, рукопожатие с проверкой версии и игры, ping/pong.
- Звук из пула плееров, с ограничением наложения и тишиной в фоне.

## Сборка и запуск

- Flutter **3.47.8** (Dart 3), Android SDK / Android Studio для Android.
- Для iOS: macOS, Xcode и настроенные инструменты Flutter для iOS. Для установки на iPhone нужна настройка подписи в Xcode.

```sh
flutter pub get
flutter analyze
flutter test
flutter run                              # выбранное устройство
flutter build apk --debug                # Android
flutter build apk --release              # Android, подписан отладочным ключом
flutter build ios --simulator --debug --no-codesign # iOS, на macOS
```

Идентификаторы приложения: Android `ru.dnepr.diana_games`, `targetSdk = 36`; iOS bundle id `ru.dnepr.dianaGames`, имя `diana_games`, отображаемое имя «Игры для Дианы». ApplicationId уникален, чтобы не конфликтовать с прежними отдельными играми (Нарды, Го, Шашки и т.д.), которые тоже собирались на скелете с прежним `ru.dnepr.games_for_diana` и имеют другую debug-подпись. Разрешения сети уже прописаны: на Android — `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE` и `CHANGE_WIFI_MULTICAST_STATE` (без последнего mDNS не ищет хоста), на iOS — `NSLocalNetworkUsageDescription` и `NSBonjourServices` с `_diana-games._tcp`.

## Как добавить новую игру за пять шагов

1. **Скопируй папку** `lib/games/backgammon/` (или любую другую) в `lib/games/<id>/`, где `<id>` — латиница без пробелов (`ludo`, `memory`, `dots`). Идентификатор попадает в ключи хранения и в сетевое рукопожатие, поэтому после первых партий его не меняют.
2. **Заполни данные игры.** В `rules.dart` — список `RuleCard` (номер, заголовок, текст), в `settings.dart` — список `GameSetting` (ключ, заголовок, подпись, иконка, значение по умолчанию). Экран правил и блок переключателей строятся из этих списков, писать экраны не нужно.
3. **Опиши сеть своей игры** в `network.dart`: `<id>GameId` — константа с латинским id; `options(settings)` — что игра рассказывает сопернику; `parseOptions(map)` — обратный разбор, который бросает `FormatException` на чужие данные; `validateMove(move)` — проверка формы присланного хода (не полные правила, только форму: транспорт зовёт это до того, как ход увидит партия). Игровые события, которые не являются ходами (бросок костей, бочонок лото, выстрел морского боя), отправляются типом `event` с полем `kind` — транспорт пропускает их без проверки, а игра слушает `network.service.events` и разбирает сама.
4. **Открой партию** в `session_page.dart`: это экран, куда ведёт кнопка «Играть» на карточке и куда `NetworkPage` передаёт живое соединение. Если `network` не `null`, читай ходы соперника из `network.service.events` и проверяй каждый через `validateMove`, а свои отправляй через `network.service.send`. Игровая логика — в файле `<name>_controller.dart` (наследник `ChangeNotifier`), а чистые правила без Flutter — в `engine/`.
5. **Добавь игру в каталог** — единственное место, где перечислены игры, — в `lib/app/catalog.dart`:

```dart
static final List<GameDefinition> games = List.unmodifiable([
  checkersGame,
  myGame,  // новая строка
]);
```

Больше ничего менять не нужно: главное окно, список игр, правила, настройки, сетевое лобби и звук общие. Заголовок карточки, слоган, иконка и цвет берутся из `GameDefinition`.

### Контракт игры

`GameDefinition` (`lib/games/definition.dart`):

| Поле | Что это |
|---|---|
| `id` | латинский идентификатор: ключи настроек `game.<id>.<key>`, поле `gameId` в рукопожатии |
| `title`, `tagline` | крупная строка и подпись на карточке, на экране партии и в приглашении по сети |
| `icon`, `accent` | иконка и цвет карточки из палитры |
| `rules` | `List<RuleCard>` — карточки `1..N` экрана правил, в том порядке, в котором их вернули |
| `settings` | `List<GameSetting>` — переключатели этой игры |
| `start(context, settings, {network})` | куда ведёт «Играть»; `network` заполнен, когда друг подключился |
| `options(settings)` | `Map<String, Object?>` с настройками игры для соперника |
| `parseOptions(map)` | обратный разбор с проверкой; `FormatException` на чужие данные |
| `validateMove(move)` | проверка формы присланного хода; `FormatException`, если ход не того формата |
| `hostSide(settings)` | место хоста в игре (например, `'white'` или `'me'`) |
| `preNetwork` (опц.) | экран перед сетевым лобби, чтобы хост мог выбрать то, чего лобби не умеет спрашивать (например, вариант нард). Если задан, список игр зовёт его перед открытием `NetworkPage`; выбор сохраняется игрой (обычно через `SettingsController.setGameString`) и читается обратно в `options(settings)` |

## Сетевая игра

Транспорт целиком лежит в `lib/network/`: `protocol.dart` — общий конверт, `network_game_service.dart` — mDNS, сервер, клиент, рукопожатие и heartbeat.

1. **Создать игру.** Хост поднимает `shelf_io`-сервер на свободном порту и объявляет службу `_diana-games._tcp` через `nsd` с именем `Diana-<КОД>` и ником игрока в TXT-записи. На экране появляются код из шести символов (алфавит без похожих `0/O` и `1/I`) и адрес `IP:порт` на случай, если поиск не работает.
2. **Найти игру.** Клиент ищет объявления в той же сети, показывает найденные игры или принимает код вручную. Можно ввести адрес `192.168.1.10:12345` — это запасной путь, когда mDNS ничего не нашёл (гостевая сеть, изоляция клиентов, отключённый multicast).
3. **Рукопожатие.** Клиент присылает `hello` с версией протокола, кодом и именем. Хост отвечает `gameConfig` — общим лобби `LobbyConfig`: `version`, `gameId`, `hostSide`, `code`, `hostName`, `options`. Устройство принимает лобби только если совпала версия протокола, `gameId` есть в каталоге **и** `game.parseOptions(options)` не бросил исключение. Иначе — вежливый отказ «У вас разные версии игры» до начала партии, а не расхождение позиций посреди игры.
4. **Партия.** Дальше идут сообщения `move`, `undoRequest`, `undoResponse`, `resign`, а также игровые события `dice` (нарды) и `event` (бочонок лото, выстрел морского боя, раздача домино — с полем `kind` внутри `data`). Ходы проверяет игра, и подключается она ровно одной функцией: лобби отдаёт транспорту `game.validateMove` через `attachGame`, и каждый присланный `move` проходит через неё до того, как его увидит партия. Если игра бросила `FormatException`, транспорт отправляет отказ и закрывает связь — обе стороны узнают об этом сразу, а не расходятся через десять ходов. Полная доска и история не пересылаются — только действия.
5. **Живучесть.** `ping` каждые 10 секунд и контроль тишины: если от соперника ничего не приходило 30 секунд, связь считается потерянной. Телефон в соседней комнате уходит в сон и без этого молча теряет соединение — снаружи это выглядит как «зависла игра».
6. **Отказы.** Чужой код, чужая игра (хост пригласил не в ту игру, чьё лобби открыто на устройстве), чужая версия протокола и незнакомые опции — всё это `FormatException` и вежливое сообщение на экране; второй экземпляр `NetworkGameService` не создаётся, лобби владеет соединением и закрывает его вместе с собой.

В каждой игре свой подход к сети:
- **Шашки, Го, Рэндзю** — одноранговая модель: оба устройства считают одно и то же состояние, ходы проверяются с обеих сторон.
- **Нарды** — хост бросает кости и рассылает результат типом `dice`, чтобы у обеих сторон было одно случайное число. Ход отправляется целиком.
- **Морской бой** — выстрел идёт типом `move` (стреляющий → цель), результат — типом `event` с `kind: 'shotResult'` (цель → стреляющий). Флоты никогда не передаются по сети.
- **Домино, Лото, Билет на поезд** — хост-авторитарная модель: хост держит все руки/колоду/бочонки, проверяет каждый ход и рассылает снимок состояния типом `event` с `kind: 'snapshot'`. Клиент только отображает и отправляет свои действия.

mDNS — только для поиска: код, проверка версии и проверка игры остаются на месте всегда.

## Звук

`lib/app/sounds.dart` — единственное место, откуда играет звук. Восемь коротких сэмплов в `assets/audio` (`move`, `capture`, `crown`, `guess`, `miss`, `win`, `lose`, `draw`) готовятся один раз при запуске: `PoolsSfxBackend` создаёт на каждый файл пул `FlameAudio.createPool` не больше чем на два голоса.

Почему не `FlameAudio.play`: он создаёт новый `AudioPlayer` на каждый вызов и не освобождает его. На Android это общий `SoundPool` с пределом в 32 потока и без события завершения: после десятков ходов новые звуки уже не играют (молчит победа и ничья), а старые потоки начинают звучать сами по себе и накладываются друг на друга.

Правила шины (`GameSounds`): выключенный звук молчит; один и тот же сэмпл не звучит дважды в пределах 90 мс; звуки хода не накладываются друг на друга; звук финала проходит сразу после хода; в фоне (`AppLifecycleState`) не играет ничего. Звук окончания партии выбирает `resultSoundName`: победа, мягкий проигрыш или спокойная ничья.

Каждая игра сопоставляет свои события сэмплам из общей восьмёрки: ход шашки — `move`, бой — `capture`, дамка — `crown`; выстрел в морском бое — `guess`, промах — `miss`, попадание — `capture», потопление — `crown`; вытягивание бочонка — `guess», закрытие числа — `move`, строка — `crown`. Лото дополнительно проговаривает числа голосом через `flutter_tts` (русская локаль), если включены и звук, и проговаривание.

## Настройки

`SettingsController` (`lib/app/settings.dart`) хранит общее и по игре:

- общее: `sound`, `nickname`, `gamesPlayed`, `gamesWon`;
- по игре: `flag(gameId, key)` и `setFlag(gameId, key, value)` с ключом `game.<id>.<key>` для булевых переключателей; `gameString(gameId, key, default)` и `setGameString(...)` — для строковых настроек (например, вариант нард — `'short'`/`'long'`). Значение по умолчанию булевого переключателя берётся из `GameSetting.defaultValue`, поэтому игры не пересекаются и не зависят от порядка загрузки.

Имя тримится, обрезается до 20 рун, пустое заменяется на «Диана», а запись того же значения не уведомляет слушателей — поэтому поле имени не пересобирается на каждый символ и клавиатура на Android не закрывается.

- `test/application/settings_test.dart` — сохранение и восстановление настроек; флаги разных игр не пересекаются; повторная запись не уведомляет.

CI — два задания:

- **Android: анализ, тесты и APK** — `flutter analyze`, `flutter test`, затем `app-debug.apk` и `app-release.apk`; оба файла лежат в артефакте `diana-games-apk`. Release подписан отладочным ключом: ставится на телефон, но не годится для Google Play. Шаг с тестами на эмуляторе включается только вручную (`Run workflow`) и не блокирует сборку.
- **iOS: сборка без подписи** — `flutter build ios --simulator --debug --no-codesign`, приложение для симулятора в артефакте `diana-games-ios-simulator`.

Каждому тесту в CI отведено две минуты: зависший тест падает со своим именем, а не держит задание. Упавшие тесты видны прямо в проверке как аннотации: имя теста и строки вокруг него.

Новый коммит в ту же ветку отменяет предыдущий прогон, поэтому одновременно висит не больше одного запуска. Тесты на `localhost` и сборка не заменяют проверку на телефонах: mDNS, звук из динамика и установку на устройство надо смотреть руками.

## Что стоит помнить, добавляя игру

- Игровой экран: всё, кроме поля, имеет фиксированную высоту, поле получает остаток — иначе оно дёргается при смене текста и появлении кнопок. Полотно игры строится один раз и оборачивается в `RepaintBoundary`. Не больше двух кнопок действия в ряду, подпись не уменьшается (многоточие вместо масштабирования).
- `SwitchListTile` и `ListTile` только на `Material`, не на цветной `Container`: иначе Flutter в debug ругается, что фон и волны нажатия скрыты, а в release волн нажатия нет.
- Движок игры — чистый Дарт без Flutter: `engine/model.dart`, `engine/rules.dart`, `engine/ai.dart`. Контроллер — `ChangeNotifier`, UI слушает через `ListenableBuilder`. Riverpod не используется для состояния игры (только `ProviderScope` в `main.dart` для совместимости).
- Звук — только через `GameSounds(settings).play(GameSound.move)` и `resultSoundName(...)`. Не импортируй `flame_audio` или `audioplayers` напрямую: пул плееров один на приложение.
- Присланный по сети ход проверяется формой в `validateMove` до применения, а отказ при несовпадении версии или игры происходит до начала партии.
- Два экземпляра `NetworkGameService` не нужны: лобби создаёт один и передаёт его партии.
- Иконки приложения рисует `tool/make_icon.py` (нужен Pillow): он перезаписывает `mipmap-*` на Android и все размеры в `ios/Runner/Assets.xcassets/AppIcon.appiconset`. Иконка повторяет логотип главного окна — наклонённая сетка, два жетона и звёздочка, — и иконки iOS сохраняются без прозрачности, как требует App Store.
